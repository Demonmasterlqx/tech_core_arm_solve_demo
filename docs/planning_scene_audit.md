# 三级兑换统一规划场景审计

审计日期：2026-10-11。依据当前 C++/MJCF、生成器、逐件 STL/OBJ 和规则状态机；CPU MuJoCo 3.3.7 加载探针。本文区分已验证结构、规划合同与尚待验证的任务可达性。没有启动 GPU、物理抓取或电机动力学。

## 已验证结论

原 `ArmSimulation` 与 `Simulation` 是独立模型。前者 7 自由度、12 个 geom，所有 geom 的碰撞 mask 为零；`mj_forward` 后 `ncon=0` 不能证明安全。它直接积分关节位置，不执行接触阻挡。后者 8 自由度、329 个 geom，只检查每个核心自己的单元—柱和地面；外壳、MARK 底座、滑块和跨核心接触均不构成原有安全检查。

新增生成器 `scripts/generate_planning_scene.py` 生成 `models/planning/scene.xml` 与 `collision_manifest.json`，引用原网格而不复制或改写源资产。实际加载为 **nq=nv=10、257 个 geom**。所有 mask 保持零，规划器按清单显式执行 `mj_geomDistance` 和下文指定的端面支撑证书，不能依赖 `ncon`。原 `ArmSimulation` 构造器拒绝额外 slide 关节，因此合并模型由独立 `PlanningScene` 持有 `mjModel/mjData`。

## 夹爪—单元配合坐标系

最终模型使用**两爪固定夹持中段**，不再使用早期探针的闭端吸附假设。不需要物理抓取仿真：只固定夹爪辅助关节角、单元相对 ee 的刚体变换，并对携带后的几何碰撞做验证。这个变换由现有 CAD 几何选择，源仓库没有提供已标定的 `T_ee_unit`。

### 源关节与张合方向

源 URDF 的左右 jaw 关节父 body 均为 j6，并不挂在空的 end_link 下。左右限位均为 [-.1,3.14] rad。在 ee 坐标系中：

| 辅助关节 | ee 中旋转轴 | ee 中轴心 / mm |
| --- | --- | --- |
| gripper_controller/end_left_joint | -Z | (15.501315,39.028906,98.910000) |
| gripper_controller/end_right_joint | +Z | (-15.498685,39.028906,99.510000) |

q=0 是张开附近姿态，不是夹紧。上游 `rm26_version3_engineering_model_moveit/config/ros2_controllers.yaml` 的 gripper 配置是 open=-.26、close=3.0 rad；控制器实现将左右 jaw 角直接设为 motor angle。open=-.26 低于源 URDF -.1 下限，这个数据不一致不能当硬件标定结果。本场景固定在两者限位内的 **q_left=q_right=2.0504 rad**（约117.48°），不执行闭合过程，也不使用空夹 close=3.0 强行压入单元。

### 固定变换与接触部位

能量单元自身 U 系：原点为开口中心，+X 从开口指向封闭大端；全长150 mm。源 `arm_tool`/ee 定义不变，规划专门使用开口 `planning_tcp`。

```text
p_ee_unit = (0, -0.015, -0.010) m
C = [ ee_Z, ee_X, ee_Y ]                  # 三列，先令 unit +X = ee +Z
R_ee_unit = C Rx(-30 deg)
quat_ee_unit_wxyz = (0.3535533905932738,
                    -0.6123724356957945,
                    -0.3535533905932738,
                    -0.6123724356957945)

planning_tcp 位于 unit 的 (0,0,0)
quat_unit_tcp_wxyz = (0.5,0.5,0.5,0.5)    # TCP +Z = unit +X
```

因此开口相对 ee 向 -Y 偏15 mm、向 -Z 偏10 mm；单元长轴与 ee +Z 平行。规划 TCP 的原点不等于原 ee。`mj_jacSite(planning_tcp)` 自动计入侧向偏置，不能继续用原 ee 的 Jacobian 去控制开口。

源两爪实体轴向约覆盖 ee Z=29–97 mm，对应 unit X=39–107 mm，落在实际中段35–110 mm；避开近端25–35 mm的过渡领圈以及110 mm以后的大端盖。真实中段白色面半径30 mm，六条灰色筋外径65 mm，筋位于截面角30°+60°k；额外绕轴 -30° 让一对灰筋朝向左右夹爪，避免把夹白面后2.5 mm悬空间隙误称为已夹持。

使用全部原 jaw 三角面投影到 ee XY，求其到中心 `(0,-15 mm)`、半径32.5 mm圆柱的最小距离：左右零间隙角约2.05077594/2.05076912 rad；留20 µm所需角约2.05040710/2.05040028 rad。共同角2.0504留至少约20 µm，接触方向接近正对的 ±X，落在对应灰筋的角宽内。这是配合几何约定，不是20 µm实物装配精度、接触力或夹持稳定性保证。

后侧爪板同时临近 `carried_unit_iron` 的**外侧圆柱面**：该碰撞代理的 X=100–110 mm、外半径32.5 mm 是中段外表面的延续。独立逐对探针的最小正间隙约19.9145 µm，近接触见证点 X=100–104.31 mm；不在孔内止口的半径≤20 mm区域。因此允许接触必须区分外侧夹持面和内孔止口，而不能仅凭 geom 名字 iron 推断其所有表面都禁止接触。

独立按类别穷举得到：所有 jaw—flange、jaw—cap 距离均至少2 mm，所有 unit—j6组件距离至少1 mm（均为探针截断距离下界）。只输出每个 jaw 最近的一个 unit geom 无法证明其他类别也安全，本审计采用逐类别检查。具体近接触 parts、距离和源哈希记录在 `models/planning/collision/jaw_prism_decomposition.json`。

### 机构方程与规划目标

设初始 E 在 W 为 e、初始核心旋转 R0，P/Q 单位rad，插入 s、升降 l 单位m：

```text
R0 = R_WO Rz(theta) Ry(phi - pi/2) Rx(alpha)
c  = (-.169, 0, .208)
B  = Rx(Q) Ry(-P)
p_open = e + R0 [c + B (.169-s, 0, -.208+l)]
axis_target = R0 B ex
```

规划目标只约束开口位置和孔轴方向，保留绕轴旋转自由度。实际单元完整姿态由机器人 FK 与固定夹持变换给出；不能把代表姿态 R0B 直接写给携带单元来代替 FK。

Q 是外层局部 +X，P 是其子层局部 -Y；升降是 P/Q 后的局部 +Z。时间顺序先 P 后 Q，不等于矩阵次序 `Ry(-P)Rx(Q)`。Q 不是单元绕自身轴自旋。公式与原 MJCF 101 组机构状态逐一比较，最大原 grip 位置误差2.22045e-16 m。新 planning_tcp 的 Z 与实际 unit X 误差1.11e-16。以上是模型一致性证据，不是实物轴线标定。

当 s=l=.1,P=pi/2,Q=0 时，开口相对初始 E 为(-.061,0,.277)。原 `.0725 m` grip site 与源 ee、当前 opening TCP 三者含义不同。合并关节顺序是七个 arm joint，随后 core0_twist/core0_flip/core0_lift；原 core0_insert 删除，s 为轨迹阶段参数，单元始终由机器人 FK 携带。

## 碰撞合同

`collision_manifest.json` 是机器可读几何分类：85 个机械臂碰撞凸几何（含分组件/分棱柱）、15 个活动核心网格凸包、柱圆柱、96 个空心单元凸段和 iron/cap 两个圆柱。外壳使用实际 OBJ AABB，局部范围约 `X=[-.201,-.112], Y=[-.224300578,.224300578], Z=[-.07837109,.48762891]`。该盒包住壳的凹区，会保守拒绝部分路径；不能称为精确网格碰撞。

| 碰撞类别 | 处理 |
| --- | --- |
| 非相邻机器人活动刚体之间 | 禁止；包括 camera、腕和夹爪 |
| 同一刚体的固定子部件 | 明确同 rigid_cluster 排除 |
| 直接相邻活动刚体 | 仅清单指定相邻 cluster 接合处的工程排除；公开可能掩盖这些相邻长部件的异常交叉 |
| 机器人—地面、mount、shell、moving core、peg | 禁止；固定安装的 j0、相邻 j1—mount 接合单独标记 |
| 携带单元—机器人 | 除下述已审计夹持面外禁止；不能排除整个手腕或夹爪 |
| `_grip` 后缀 jaw part—tube / iron外壁 | 固定抓持的指定近接触区域，容许触碰及最多 .1 mm数值穿深；不是孔内止口面豁免 |
| 携带单元—shell、地面、mount、slide | 禁止 |
| 单元内孔—柱 | 空心代理检查，不能整体排除；孔径40/柱径36，径向名义间隙2 mm |
| 单元铁止口—柱端 | 仅插到底 s=.1 附近允许端面接触，数值穿深不超过 .1 mm |
| 单元开口法兰—MARK/底座/内环前面 | 仅合法座合端面接触；按具体 geom 对检查，穿深不超过 .1 mm |
| 核心内部同一运动机构部件 | 不是机器人避碰对象；其内部拓扑仍属现有近似机构，不由此宣称无自碰 |

推荐自由空间非装配物体最小距离 **1 mm**；孔柱要求另保留 **.5 mm 径向余量**，以径向/轴向几何一致性补充窄相距离。P=90° 后，单元轴局部 X=-.061，95 mm 后盖最靠壳 X=-.1085，与壳前沿仅 **3.5 mm**。统一 5 mm 膨胀会误拒合法名义终点。轴向 stop 与座合对不能套用 1 mm 自由空间阈值，但不能无限穿透。

原 HKUST 中央电磁铁顶端超出名义 E 约 4.63 mm，若与规则100 mm 孔深止口同时严格碰撞会矛盾。本合并场景沿用已公开的规则柱圆柱代理，替代 `pillar_side_*` 外观碰撞；详细替代表列入清单。其余 moving core 按原网格凸包检查。必须在结果中说明此几何合同。

### 接触区域与共面数值问题

固定夹持许可在构造时检查整个带 `_grip` 标签的凸几何：jaw 与单元必须属于同一 welded body，全部凸顶点转换到单元坐标后 X 必须位于34.8–110.2 mm，YZ凸投影到轴线的最小半径必须至少32 mm。由此证明整个允许部分局限于外壁区域，不进入半径20 mm的内孔止口。每个状态仍检查这些对的距离及.1 mm穿深限制。MuJoCo零距离结果可能没有有效 `fromto` 见证点，因此不以未赋值的世界原点判断接触区域。该证书假定构造后不外部改写焊接抓持几何。

MuJoCo 3.3.7 native CCD 对几乎共面的 flange—底座端面曾报告约−47 mm，切换 legacy 得到约0.04–0.3 µm正距离；把单元精确对准机构仍可复现错误。原始探针在 `artifacts/planning_scene_audit/mating_compare.{cpp,txt}`。当前对**清单指定的装配端面对**计算柱轴上的精确凸支撑区间：网格逐顶点，圆柱用解析支持函数。单元最小投影减核心最大投影为 gap；插入中要求 gap≥0，座合后要求 gap≥−.1 mm。满足条件才接受，不能证明则保守拒绝。这证明分离平面或最多.1 mm的轴向分离平移，不把gap冒充精确三维有符号距离，也未扩大容差。内孔壁、未命名部件和其他接触仍用原显式窄相距离检查。

### 保守分解及覆盖验证

整块 j4/j6 网格凸包在源 home 误报约28.0 mm自碰。原14,750/10,414个三角面逐对包围盒没有表面相交候选；分别按6/5个源连通组件建立凸包后，home非相邻臂自碰检查全部满足1 mm，不增加距离2关节的豁免。

整块 jaw 凸包也会填平夹爪凹口，无法表达实际夹持。因此采用原 STL 连通组件的 XY 投影外轮廓，填内部螺孔（仅增加实体）、划分为凸多边形，再沿该组件完整 Z 范围挤出；左右分别33/35个棱柱。投影外边界和Z各外扩0.1 µm避免浮点裁切。对**全部源三角面投影**与棱柱并集做布尔差，五个组件未覆盖面积均为0；全部源顶点到并集的外侧距离均为0。Z包络包含每个源顶点，由线性插值也包含整张三角面。这是实际源表面包络验证，不把某个分解优化阈值当Hausdorff精度承诺；填螺孔和按轴挤出仍可能保守拒绝局部路径。

离线分解为 NumPy + Shapely 2.2.0，单线程约0.08–0.25 s，无GPU。探索过的CoACD过细分产物未用于最终模型，并已清理。默认生成只校验并复用入库棱柱，无需第三方Python包；`--regenerate-jaws` 才需要离线依赖。各源/产物SHA-256、全部覆盖审计与近接触 parts 列表在 `jaw_prism_decomposition.json`。

能量单元近端实际领圈到X=35 mm；原25 mm flange代理会漏掉25–35 mm外形。本规划模型将空心flange覆盖0–35 mm，tube覆盖35–100 mm；100–110 mm外壁由iron圆柱覆盖，110–150 mm为大端cap。仍保留96个空心段，孔半径20 mm。外侧多边形改为外切而非内接，确保圆形外径被包住；由此固定夹持代理最大约17.36 µm穿深，低于允许的.1 mm，原CAD几何仍留约20 µm。

内孔同样采用48边外切多边形：每段内侧顶点为 `(y,z)=(.020,±.020 tan(pi/48))`，边中点半径20 mm，角点半径最大为 `20 sec(pi/48)=20.0429134 mm`。因此相比规则圆孔，代理内孔局部最多向外扩大 **42.9134 µm**；这不是保守缩小孔，外轮廓的保守覆盖不能推广为整个空心实体的完全保守覆盖。名义2 mm孔柱间隙与3 mm径向错位拒绝测试仍有效，但不能据此声称已排除这一离散尺度内的圆孔壁穿透。

仅检查轨迹节点不足。当前验证器按三次关节插值对每条边采样，按最大关节步长及最少子步控制密度，并检查每个样本的FK、轴向、装配一致性和碰撞。输出最近geom对、阶段、距离与采样数。该离散检查没有证明所有几何在采样间的位移上界，也不是严格连续碰撞证明；独立更密采样结果应与主规划结果分开报告。

## 标准三级套件与验收

所有算法固定同一 grasp、场景 placement、碰撞阈值、关节限位、目标节点、seed 与计时边界。计时包含单次完整规划的目标生成、IK、必要避障/恢复及最终密集验证；另外报告模型加载和缓存预处理时间，冷启动与重复请求分开。规划 <3 s 是计算预算，不是执行三级动作仅3 s。使用三次平滑关节插值，按1 rad/s mock速度和2 rad/s²规划加速度限值时间化；最后实际驻留 .5 s，超过规则 .4 s阈值，再调用规则 confirm。这些限值不代表硬件标定能力。

阶段为：已携带 home/起点 → 开口在 E 法向外 .04 m 的预接近 → 接近 s=0 → 插入 s=0.. .1 → 升降 l=0.. .1 → P=0..pi/2 → Q=0..目标 → .5 s 驻留 → confirm。进入接近前核心已 ready。插入过程中 l=P=Q=0，升降过程中 P=Q=0，P 过程中 Q=0；上一阶段端点至少产生一条 observation，不能把整段跳到终点欺骗逐步骤判定。

2026-10-11 起，规划入口先对 E 法向外 40 mm 的预插入位姿直接做一次 IK，再从实际起点向这个解做关节空间线性连接。连接以最大关节步长 0.02 rad 采样，目标由 FK 生成，沿用统一的时间参数化、碰撞与关节限位验证；随后仍按原有任务路径逐点求解。显式提供 `approach_joint_waypoint` 的调用保留实际起点到该路点的连接，并以路点为预插入 IK 初值。此前保存的实验结果属于旧版接近路径，不能直接当作此版本的性能测量。

当前 `scenario_suite()` 固定 **6 development +14 confirmation +3 negative**。完整参数以该函数和导出的套件JSON为准；难例保留在统计中，不承诺每个正常请求均可行。

| 组 | 当前覆盖 |
| --- | --- |
| development 6例 | nominal、low、yaw、roll、tilt、qzero；Q涵盖−60°到+60°及0 |
| confirmation 前8例 | Q=±90°、z=.6、左右偏置、倾斜、roll、混合姿态 |
| confirmation 边界6例 | z=.7、theta=±45°、alpha=45°、y=.1/.3；不是atlas开发条目 |
| negative 3例 | 安装X=.65的远距请求、固定插口阻挡盒、核心越前平面 |

径向3 mm插口错位、非法关节/NaN、跳过阶段等另由几何/合同单测检查，不伪装成基准套件新增样本。套件的20个正常请求用于评估成功率与失败原因；3个negative用于检验拒绝，不能把拒绝耗时混入成功规划加速比。

成功必须同时满足：全部必需阶段存在、每点/每边碰撞合同通过、携带单元由 FK 得到、装配端点闭合误差合格、`AssemblyRules` 确认成功。算法耗时统计应报告成功数、失败原因、median/p95/max，比较逐场景原始耗时与加速比；不能仅剔除难例后声称降90%。
