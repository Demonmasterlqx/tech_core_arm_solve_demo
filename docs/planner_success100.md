# 两后端各 100 次整体成功率复测

2026-10-11，算法提交 `fd6e983`。Baseline 和 RigidCache 在相同 100 个请求上的有效轨迹成功率均为 **31%**；完整转满 Q 双向 ±90° 的比例分别为 **19% 和 18%**。本次只做评测，没有修改算法或参数。

## 输入与判定

使用此前固定的全部 100 个扩展位姿，每个位姿测试一个起点：偶数编号使用七关节零位，奇数编号使用装配预设，各 50 次。选择规则在本轮开始前固定，不根据可达性、碰撞或历史成功结果筛选。两个后端各执行相同的 100 个请求，共 200 次规划调用。

核心相对名义位置 XYZ 各 ±20 cm、roll/pitch/yaw 各 ±90°，使用已有种子 `20261012` 的六维拉丁超立方输入；这批位姿曾用于旧版评测，不能称为新盲测。安装为默认 Demo 安装，核心位姿限制关闭，每次在线预算 5 s，仿真速度倍率 4，不使用逐位姿保存解或跨请求热启动。[固定输入](evidence/planner_success100/cases.csv) 和 [协议](evidence/planner_success100/protocol.json) 保存了范围、分母、起点分配和哈希。

“有效轨迹”沿用当前 best-effort Q 规则：接近、对准、插入、升降和 P 翻转全部完成，Q 能转多少转多少，最后驻留，并通过整条轨迹的无缓存复验。完整双向 ±90° 单独统计。起点碰撞、任何阶段逆解/碰撞失败、阶段预算耗尽及复验失败均保留在分母中。

## 实测结果

| 指标 | Baseline | RigidCache |
| --- | ---: | ---: |
| 有效轨迹成功率 | **31/100（31%）** | **31/100（31%）** |
| 完整双向 ±90° | 19/100（19%） | 18/100（18%） |
| 有效但 Q 仅部分行程 | 12/100 | 13/100 |
| 有效但 Q 完全不动 | 0 | 0 |
| 零位起步成功率 | 16/50（32%） | 17/50（34%） |
| 装配预设起步成功率 | 15/50（30%） | 14/50（28%） |
| 全部请求平均在线耗时 | 1.121 s | 1.100 s |
| 成功请求平均在线耗时 | 1.643 s | 1.586 s |
| 全部请求最长在线耗时 | 3.278 s | 3.317 s |

每个后端的 69 次失败分类如下；各行互斥，总和包含所有失败。

| 失败位置/原因 | Baseline | RigidCache |
| --- | ---: | ---: |
| 实际起点已经碰撞 | 17 | 17 |
| 预插入目标碰撞 | 2 | 3 |
| 装配阶段逆解失败 | 32 | 31 |
| 求解路径碰撞 | 15 | 13 |
| 接近段搜索预算耗尽 | 3 | 5 |
| 合计 | 69 | 69 |

逆解失败中，P 翻转阶段分别占 29 和 28 次，升降各 2 次、插入各 1 次。接近段预算是分配给路径搜索的子预算，因此可以在总耗时尚未达到 5 s 时耗尽。这些失败仅表示当前求解器在给定预算下未得到合格轨迹，不等于已证明物理不可达。

相同 100 请求在历史提交 `8859a1c` 中，两后端也各成功 31 次，但完整双向 ±90° 分别仅 6 次和 5 次。本次没有丢失原成功请求，也没有配对成功请求的 Q 总行程减少。近期 Q 局部换解提高了末段可转范围；当前整体成功率的主要限制仍出现在 Q 之前。

## 验证与复现

两个进程均正常完成，逐例结果各恰好 100 条，无缺失、重复或缓存/无缓存验收不一致。62 条成功轨迹全部通过额外的独立 URDF/NumPy 审计：按在线采样数的两倍检查 FK、任务阶段、机构链、起点、关节限位、Q 范围、时序及解析速度/加速度。138 条失败记录仅检查有限字段和关节范围，不将失败前缀认证为可执行轨迹。碰撞复验使用项目 C++ 碰撞模型，独立 URDF 审计不验证网格碰撞。

- [Baseline 逐例结果](evidence/planner_success100/baseline.csv)、[RigidCache 逐例结果](evidence/planner_success100/rigid_cache.csv)：包含所有失败原因、Q 范围及耗时。
- [统计汇总](evidence/planner_success100/summary.json)、[200 条记录的独立审计](evidence/planner_success100/urdf_audit.json)。
- [执行元数据](evidence/planner_success100/run_manifests.json)、[证据索引与资源清理](evidence/planner_success100/evidence.json)：源文件、静态库、输入、冻结二进制及结果哈希。

在仓库根目录运行，输出目录必须是新目录：

```bash
cmake --build build -j4
python3 scripts/run_planner_quality.py --suite docs/evidence/planner_success100 \
  --output artifacts/success100-baseline --split all --method baseline --cpu 0 --timeout 5
python3 scripts/run_planner_quality.py --suite docs/evidence/planner_success100 \
  --output artifacts/success100-rigid --split all --method rigid_cache --cpu 2 --timeout 5
```

本次使用 CPU 0/2 运行两个后端、CPU 4 运行独立审计，CUDA 关闭，没有创建渲染器。评测子进程均已回收；原始轨迹、冻结程序、轮转日志和审计调用脚本保留在 `artifacts/planner_success100_20261011/`。旧报告的 200 请求评测与“已证可完成样本”条件成功率不作为本次整体成功率的分母。
